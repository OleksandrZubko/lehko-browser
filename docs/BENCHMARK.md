# Протокол вимірювання

## Умови

Тестова машина: Mac M1, 8 ГБ RAM. Використовувати одну версію Chrome Stable ARM64 та три окремі профілі, створені `npm run open:lab -- MODE`. Основний профіль не використовувати. Для кожної серії — однакові розширення й версії, підключене живлення, вимкнений Low Power Mode, закриті інші ресурсомісткі програми. Не запускати конфігурації одночасно.

| MODE | Штатний Memory Saver | Легко |
|---|---|---|
| baseline | вимкнено | вимкнено на сторінці розширень |
| native | Balanced | вимкнено на сторінці розширень |
| extension | вимкнено | увімкнено, 15 хвилин, hostname дозволено |

Встановити однакові uBlock Origin Lite, Bitwarden і React Developer Tools у кожен профіль. Не використовувати особистий vault: перевірити Bitwarden на тестовому обліковому записі. Вимкнути відновлення попередньої сесії для вимірювань і попереднє завантаження сторінок однаково в усіх профілях. Версії й налаштування записати в `--conditions`; стан Memory Saver перевіряється вручну в `chrome://settings/performance`. Колектор не встановлює і не перевіряє ці налаштування.

## Відтворювана синтетична серія

```sh
npm run benchmark:fixtures
```

Залишити сервер працювати. У другому терміналі:

```sh
npm run open:lab -- extension twenty
```

Так само для `baseline`, `native` і `five`. Сервер слухає тільки `127.0.0.1:8917`; кожна сторінка виділяє 32 MiB. Це контрольована перевірка механізму, а не заміна вимірювань реальних сайтів.

Після відкриття набору послідовно відвідати всі вкладки, повернутися до останньої та **20 хвилин не взаємодіяти з браузером**. Для extension спочатку дозволити `127.0.0.1`, закрити popup і лише тоді почати відлік. Не скорочувати таймер через DevTools у продуктивних вимірюваннях. CPU/RSS заміряти наступні 60 секунд. Для кожного нового повтору закрити всі вкладки набору й відкрити набір знову; кількість вкладок має бути рівно 5 або 20.

Знайти PID головного процесу за точним `--user-data-dir` (launcher друкує PID; при повторному відкритті вже запущеного профілю PID буде іншим). Зібрати дані:

```sh
python3 scripts/collect_metrics.py \
  --pid 12345 \
  --profile '/absolute/path/to/Browser/artifacts/profiles/extension' \
  --mode extension --scenario twenty --repeat 1 \
  --experiment m1-synthetic-v1 \
  --conditions 'AC; low-power-off; fixture-v1; uBOL=X; Bitwarden=Y; ReactDevTools=Z; 20min-idle' \
  --duration 60 --interval 5
```

Підставити справжній PID, абсолютний шлях і фактичні версії. Колектор відмовляється вимірювати PID, якщо команда не містить точного шляху окремого профілю. Він не записує адреси вкладок, командні рядки або шляхи профілю в JSON.

Виконати по **три повтори для кожної конфігурації в обох сценаріях**: разом 18 запусків. Чергувати порядок: baseline/native/extension, native/extension/baseline, extension/baseline/native. Перед новим запуском закрити попередній браузер і дочекатися стабілізації системи. У кожній серії значення `--conditions`, duration та interval однакові.

```sh
python3 scripts/report_metrics.py artifacts/metrics --experiment m1-synthetic-v1
```

Звіт не формує висновок за неповними, дубльованими чи непорівнюваними наборами. Для кожного режиму порівнює медіану середніх значень трьох запусків. Значення CPU — відсотки одного ядра; збільшення на 5 означає +5 процентних пунктів.

## Що означають вимірювання

- Пам’ять — сума RSS головного процесу й усіх його нащадків, включно з GPU, workers і розширеннями. Спільні сторінки можуть враховуватися кілька разів. Це показник для порівняння, не точна кількість унікально зайнятої фізичної пам’яті. Зменшення RSS саме по собі не доводить зменшення системного memory pressure.
- CPU — сума `%cpu` з `ps`, тобто згладжена оцінка ОС. Для точного профілю енергії потрібен окремий Instruments-прогін; автономність батареї тут не заявляється.
- Swap — загальносистемне значення `vm.swapusage`; не приписувати весь swap браузеру.
- Час повернення — від вибору вкладки до готовності сторінки до взаємодії; для синтетичних сторінок — до появи тексту стану. Виміряти п’ять найстаріших вкладок у кожній конфігурації після збору RSS/CPU; додати фактичні значення повторними `--restore-latency-ms` або записати окремо у звіт. Не змінювати зібрані JSON заднім числом.

## Сумісність і збереження роботи

На справжніх сайтах окремо перевірити:

- uBlock Origin Lite: встановлення з магазину, popup, блокування на контрольній сторінці, збереження налаштувань після перезапуску.
- Bitwarden: тестовий вхід, popup, заповнення тестового логіна, блокування vault, повторний запуск. Власне розширення не обіцяє зберігати розблокований vault.
- React Developer Tools: панель Components і вибір компонента на тестовому React-застосунку.
- Музика, відеодзвінок зі screen sharing, форма та upload/download **на недозволених hostname** продовжують роботу після 20 хвилин. Справжні чернетки не використовувати. Окремо перевірити активну вкладку в другому вікні й закріплену вкладку дозволеного сайту.
- Зупинка service worker не скидає таймери; повне закриття всіх процесів браузера починає нову сесію з нульовими лічильниками й збереженими налаштуваннями.

## Критерій переходу

Ціль для 20 вкладок: RSS щонайменше на 15% нижчий, ніж у Balanced Memory Saver, CPU не вище ніж на 5 п.п., без втрати роботи в захищених сценаріях. Перевірка на синтетичному наборі — попередній результат; перед форком повторити протокол на зафіксованому наборі реальних сайтів із записаними URL та умовами.

Якщо критерій не виконано, зберегти звіт і зупинити перехід до форку. Середовище компіляції Chromium та оновлення нативного браузера — окремий наступний етап.
