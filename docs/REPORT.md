# Перевірка реалізації — 28 жовтня 2026

**Статус:** прототип розширення працює. Перевагу над Balanced Memory Saver ще не виміряно; критерій переходу до власного Chromium-форку не підтверджено.

## Перевірено

| Перевірка | Результат |
|---|---|
| TypeScript strict / збірка | Проходить |
| Політика й інтеграція зі сховищем/подіями (Node.js) | 35 тестів проходять |
| Колектор і генератор звітів (Python) | 6 тестів проходять |
| Chrome Stable 156.0.8078.73, macOS ARM64, окремий тимчасовий профіль | Реальний MV3 worker встановлюється й відповідає |
| Інтерфейс | Дозвіл точного hostname після підтвердження, таймер, пауза/відновлення, причини пропуску перевірені |
| Реальний `chrome.alarms` → політика → `tabs.discard` | 6 придатних вкладок вивантажено за один прохід |
| Захищені вкладки в браузерному тесті | Активна, закріплена, `autoDiscardable: false` і недозволена сторінка з текстом у формі збережені |
| Реальна зупинка service worker через CDP | Після підтвердженого `stopped` новий worker відновлює таймери зі `storage.session` |
| Повернення до вкладки | Вивантажена вкладка завантажується знову при активації |
| Повний перезапуск браузера | Скидання сесії зі збереженням налаштувань перевірено інтеграційним тестом із моделлю API; окремий реальний restart-прогін не виконано |
| Активні вкладки різних вікон, звук, завантаження, зміни вкладки перед дією | Перевірено тестами політики/контролера; справжні дзвінки й upload ще не перевірено |

У функціональному браузерному тесті часові мітки тимчасової сесії зсунуті на 16 хвилин, щоб перевірити дію політики без очікування. Продуктовий таймер і код політики не змінювалися. **Цей тест не є продуктивним бенчмарком.**

Chrome під час discard надсилає `onReplaced` і змінює ID вкладки. Реальний тест виявив, що глобальна інвалідація через цю подію зупиняла прохід після першої вкладки. Тепер локальні події інвалідують лише відповідну вкладку, а активація й зміна політики — весь прохід. Додано регресійні тести.

Локальні докази: `artifacts/browser-smoke.json`, `artifacts/browser-smoke-state.json`, `artifacts/popup.png`. Профілі автоматизованих тестів видалено після завершення.

## Перевірка колектора на справжніх процесах

Окремий 10-секундний headless-запуск Chrome із п’ятьма простими `data:`-сторінками, без розширення; 6 вибірок. Мета — перевірити працездатність збору, а не порівняти браузери.

| Показник | Фактичне значення |
|---|---:|
| Середня сума RSS дерева процесів | 1087.01 MiB |
| Середня сума `%cpu` з `ps` | 34.25% одного ядра |
| Максимум процесів | 11 |
| Загальносистемний swap, початок / кінець | 5942.75 / 5942.75 MiB |

Дані: `artifacts/collector-smoke.json`. Це короткий запуск одразу після відкриття браузера: CPU включає стартове навантаження. RSS може повторно рахувати спільні сторінки; swap належить усій системі. Ці цифри не описують споживання готового прототипу й не є його накладними витратами.

Контрольована серія з 18 запусків по 20 хвилин стабілізації плюс збір/перевірка займає понад 6 годин. У цій реалізації завершено функціональний прототип і перевірку засобів вимірювання; цю серію ще не виконано. Для неї потрібні послідовні запуски в однакових умовах, зі звичайними таймерами, без інших ресурсомістких застосунків. Готові launcher, синтетичний набір, колектор і генератор порівняння описані в [BENCHMARK.md](BENCHMARK.md).

## Залишилося перевірити перед переходом до форку

- Повну контрольовану серію й щонайменше 15% економії RSS проти Balanced Memory Saver без регресії CPU понад 5 п.п.
- uBlock Origin Lite, Bitwarden і React Developer Tools із Chrome Web Store: реальне встановлення, функції та перезапуск. Ці три сторонні розширення під час автоматизованих тестів не встановлювалися.
- Справжні музику, дзвінок, screen sharing, передачу файлів і форму на недозволених hostname під час звичайного 20-хвилинного простою.
- Час повернення до сторінок, повний реальний перезапуск браузера та повторення вимірювань на погодженому наборі реальних сайтів.

**Рішення:** підстав переходити до власної збірки Chromium за вимірюваннями поки немає. Інсталюваний прототип готовий до особистого тестування на безпечних сторінках.
